# Composite Source Resource Probe

Status: RSC-R03 measured; design decision branch 1 applied.

This record checks the relationship between composite source-count admissions and deep composite chains. A chain requested with `--depth N` has `N + 1` admission edges. All experiments were isolated in child processes; the default-boundary matrix completed without process termination. Explicitly raised and unbounded source limits did reproduce a loading-thread stack overflow at one high-depth, small-stack point.

## Probe implementation

[`config_composite_resource_probe.rs`](../examples/config_composite_resource_probe.rs) supports `--stack-bytes N`. With this option, construction, loading, and destruction happen inside a worker thread with that stack size. The child process remains supervised by its existing 30-second watchdog. The parent and child receive the same address-space limit through inheritance.

| Effective limit check | `/proc/<pid>/limits` reported soft and hard `Max address space` as `1073741824 bytes` |

The short-chain check used:

```bash
/usr/bin/time -v timeout --signal=TERM --kill-after=2 30s \
  prlimit --as=1073741824 --core=0 -- \
  sh -c 'grep "Max address space" /proc/$$/limits; exec target/debug/examples/config_composite_resource_probe --shape chain --depth 8 --limits default --stack-bytes 2097152'
```

It exited 0 in 0.01 s, printed all lifecycle stages through `destroyed`, reported `child_exit=exit status: 0`, and measured 2,240 KiB maximum RSS. The exact 1 GiB address-space limit was visible from inside the limited process. `/usr/bin/time -v` measured peak RSS for each run; the address-space limit is not represented as a strict RSS cap.

All matrix invocations used this protected form (with the profile binary and workload arguments varied):

```bash
timeout --signal=TERM --kill-after=2 30s \
  prlimit --as=1073741824 --core=0 -- /usr/bin/time -v \
  target/{debug,release}/examples/config_composite_resource_probe \
  --shape chain|wide --depth N --limits default|raised|unbounded \
  --stack-bytes 2097152|8388608 [--label-bytes 4096]
```

Each point was repeated three times. No run timed out or hit the address-space limit. Stack-overflow messages said `(core dumped)`, but `--core=0` prevented a core file; no core artifact was found in the worktree.

## Results

### Default boundary

The complete default matrix covered debug/release, chain/wide, 2 MiB/8 MiB worker stacks, and depths 254/255/256 (255/256/257 admission edges), three runs per point: 72 runs total. All reached `destroyed` and exited 0. At depths 254 and 255, loading succeeded. At depth 256, loading returned the structured `SourceLimitExceeded` result, after which destruction completed normally. This matches the default 256-admission budget and did not reproduce a default-boundary process failure.

Maximum RSS was 4,928 KiB (debug chain), 4,032 KiB (release chain), and 2,240 KiB (wide). These are observed values from this host, not general memory bounds.

### Raised and unbounded limits

At depth 256 (257 edges), the raised debug chain on a 2 MiB stack passed three times. At depth 1024 (1,025 edges), the raised and unbounded chain on a 2 MiB stack failed three times in each debug and release profile. The last lifecycle stage was `loading`; the worker emitted `thread '<unknown>' ... has overflowed its stack` and `fatal runtime error: stack overflow, aborting`. The child supervisor reported `signal: 6 (SIGABRT)` and the probe process exited 1. Maximum RSS at failure was 9,856 KiB in debug and 13,888 KiB in release, which is inconsistent with an address-space or memory-pressure failure.

At the same depth with an 8 MiB stack, the raised and unbounded chains completed all lifecycle stages in both profiles (debug maximum RSS 25,984 KiB; release 24,192 KiB). The raised wide shape at 1,025 edges completed on both stack sizes in debug and release, with 2,240 KiB maximum RSS. The unbounded wide shape was checked at depth 256 on both stacks and profiles and completed in all runs.

The first repeated abnormal point occurred at depth 1024 on a 2 MiB stack. In accordance with the stop rule, no raised or unbounded runs at depth 4096 or 8192 were attempted. This matrix therefore does not claim safety at greater depths.

### Label-width comparison

At the shallow ordinary point (depth 8, 9 edges, default limits, 2 MiB stack), debug/release and chain/wide were run with short labels and with `--label-bytes 4096`, three times per point (24 runs total). Every run completed, and `/usr/bin/time -v` reported 2,240 KiB maximum RSS for each. This comparison did not show an RSS change at this scale; it does not establish an asymptotic memory bound.

## Decision

This is design branch 1: the default 256-admission boundary completed or returned a structured budget error in the tested configurations, while explicitly raised or unbounded limits exposed a high-depth chain stack overflow on a 2 MiB worker stack. No confirmed default-boundary crash was found, so this task does not change the composite execution protocol, default values, public API, error category, or wire representation.

The bilingual guides and design documents now state that `max_sources` counts cumulative descendant-source admissions (the scope root is excluded), not composite nesting depth. They advise keeping a conservative finite limit and flattening deep compositions. The measurements are specific to the recorded host, toolchain, profiles, workloads, and stack sizes; they are not a cross-platform safety guarantee.
