# qubit-config Coverage Policy

[Simplified Chinese](coverage_policy.zh_CN.md) | English

This policy describes the package-scoped, per-file coverage gate for `qubit-config`.
The project uses the shared coverage generator for instrumentation and report
production, then applies its own file-level policy to `src/`.

## Enforcement

Run the complete local coverage flow with:

```text
./scripts/check-project-coverage.sh
```

The script runs `.infra/bin/coverage.sh` to generate the shared report at the
repository root as `coverage.json`, then invokes:

```text
python3 -B scripts/check-coverage-files.py coverage.json --config .infra/coverage/coverage.json
```

The CI `coverage-files` job downloads the `coverage-reports` artifact produced
by the `rust-ci` job and checks `artifacts/coverage/coverage.json` against the
same `.infra/coverage/coverage.json` policy. The shared coverage summary and
badge remain useful aggregate views; they do not replace the per-file gate.

The policy scope is package `qubit-config`, with source directory `src/` and
these thresholds for each non-exempt source file:

- functions: at least 95%;
- lines: greater than 90%;
- regions: greater than 85%.

The checker fails when the report or policy is missing/invalid, when expected
source files are absent from the report, or when a non-exempt file is below a
threshold. The most recent pre-change report available in the original
checkout was generated by `cargo-llvm-cov 0.8.6` and has a file timestamp of
2026-10-06. Its per-file counters justify only these current exceptions:

The shared `.infra/coverage/coverage.json` follows the strict schema consumed by
`.infra/bin/coverage.sh`. The project checker keeps module-only source
classifications in `.infra/coverage/non-executable-files.json`; it requires
these paths explicitly and does not silently ignore a file because it is absent
from the report. The available report cannot verify the YAML scanner refactor
because the current Rust build is blocked by an external path-dependency error.

## Maintaining the Policy

Do not add a business branch as an exception. A proposed exception needs a fresh
coverage report, the exact attribution gap or unreachable defensive branch, and
a focused test for the observable behavior. Update the machine-readable policy
and both language versions of this document together. Remove an exception when
a Rust/LLVM or `cargo-llvm-cov` update fixes the attribution issue.

The checker can be run independently against an existing report:

```text
python3 -B scripts/check-coverage-files.py coverage.json --config .infra/coverage/coverage.json
```
