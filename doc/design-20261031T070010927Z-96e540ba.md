## 方案选择

采用现有边界内的局部完善：保留 `Config`、`ConfigReader`、`ConfigSerdeExt`、错误枚举及 wire 格式，在私有诊断构造和既有文档流水线上修改。

不采用通用格式化 Serde `Expected` 的方案：即使接口接收静态引用，其格式化实现也可能含应用提供的文本，会破坏现有脱敏约定。不新增公共错误变体、schema DSL 或文档执行框架：当前四项收益不需要这些接口和迁移成本。

## CFG-001：安全诊断

### 私有构造入口

在 `ConfigDeserializeError` 的定义文件增加三个私有关联构造函数，不新增类型或公共 API：

```rust
pub(crate) fn shape_mismatch(path: &str, expected: &'static str) -> Self;
pub(crate) fn tuple_length(path: &str, actual: usize, expected: usize) -> Self;
pub(crate) fn tuple_has_extra_items(path: &str, expected: usize) -> Self;
```

它们返回现有 `Message { message, path: Some(...) }`，转换到公共错误后仍是 `ConfigError::DeserializeError`。文案使用英文，分别表达：

- `configuration value must have shape: {expected}`；
- `configuration tuple has length {actual}; expected {expected}`；
- `configuration tuple has more elements than expected length {expected}`。

`shape_mismatch` 的参数只允许内部 helper 调用点提供的固定字面量，例如 `a scalar`、`a map`、`a sequence`、`an enum`、`a single enum variant`。不把任意 Serde `Expected`、`Unexpected`、输入值或自定义错误消息传入该构造函数。`type_error` 改为直接调用它，保留现有路径附着方式。

### 长度与错误顺序

原生集合在 `sequence` 已具有 `values.len()`。以 `if let Some(expected) = expected_len` 检查，不匹配时调用 `tuple_length`。这包括空集合、过短、过长以及元组结构体；匹配时保留原访问流程。

标量拆分列表是惰性消费。访问成功后仍只调用现有 `has_remaining()`，确认多余项后调用 `tuple_has_extra_items`，不扫描剩余尾部、不伪造完整实际长度。`has_remaining()` 的预算或转换错误继续优先传播。过短列表由目标 visitor 报出的错误继续保留，不尝试从已脱敏消息反推出预期长度。

目标是提高库已知失败的可解释性，不改变输入接受集合、visitor 执行次数、转换收费、短路读取、错误类别或根相对路径。

### 行为验证

在已有公共集成测试中覆盖：原生集合过短/过长/空；标量列表多余项；成功元组；嵌套字段及 section 路径；map/sequence 形状不匹配；既有 secret-canary 自定义消息及恶意 `Expected` 不泄露；原有尾部预算和转换错误优先级不变。

精确长度测试只对库实际知道完整长度的输入断言。对标量列表只断言多余项及目标长度，不要求完整实际长度。消息不是公共稳定协议；测试聚焦此次诊断内容，程序判断仍使用 `kind()`、`path()`。

## CFG-002：三组规范教程示例

沿用现有“示例文件是规范源、中英文代码块精确对应”的机制，新增：

| 示例 ID / 新文件 | 使用位置 | 自校验内容 |
| --- | --- | --- |
| `config_custom_target` / `examples/config_custom_target.rs` | 两种指南的 Custom Target Types | 普通读取、自定义 FromConfig 委托、section 插值、普通读取保留占位符、错误类别和根路径 |
| `config_read_policy` / `examples/config_read_policy.rs` | 两种指南的读取策略小节 | env_friendly 布尔值、分隔列表、临时策略不修改 Config 默认策略 |
| `config_structured_guide` / `examples/config_structured_guide.rs` | 两种指南的基础结构化读取小节 | server 字段投影及 host、port 结果 |

以现有完整教程为起点，保持业务语义，按仓库规范拆开 import，使用既有七行文件头；中英文指南对应代码保持相同，不依赖真实环境变量或网络。需要 `ConfigSerdeExt` 的调用必须显式导入；不因示例新增生产依赖或 feature。

`EXAMPLE_DOCS` 加入三项，规范示例总数从 9 变成 12。检查器的解析范围不扩展到全部 Markdown 代码块，因为现有代码还包含有意依赖上下文的片段。保留每份指南剩余片段，并说明完整教程与上下文片段的区别；本轮不宣称所有 Rust 片段均被编译。

在 `check_doc_examples_tests.py` 中检查三组 ID 的必需性，并验证缺少任一语言标记、代码漂移和缺少规范文件可被发现。优先复用现有临时目录测试机制。`.infra/project-ci-check.local.sh` 只新增三条本 crate 的 `cargo run --locked --example ...`，使其断言实际执行；不增加下游测试任务或新的 CI job。

指南关于错误脱敏的说明同步为：外部 Serde 预期/实际描述仍被过滤；库内部已知的结构名称与长度可以保留。README 的既有安装说明和快速开始不需要改写。

## CFG-004：内部 Rustdoc 补齐

- `source_index.rs`：补充 `is_exact`、`push_origin`、`push_property`。明确 Exact 不能追加、错误形态调用会 panic，node ID 与 property index 不同，来源槽应与 arena 节点同步增长。来源 property 表在构造期可短暂晚于来源槽登记，不误写成每一步都已可解引用。
- `source_seq_access.rs`：解释 `context`、`values`、`session` 的借用和共享收费责任；文档化 `new` 及其原始外层索引保留规则。trait 方法补充非显然语义，不逐行复述。
- `scalar_seq_access.rs`：补充类型级 Rustdoc，说明一次标量输入准入、惰性 item 消费、原始索引和共用会话；`has_remaining` 会消费一次探测且可能产生预算或转换错误，不应描述成纯查询。
- CFG-001 新 helper 的参数、返回值和脱敏前提随实现添加英文 Rustdoc。

本项不移动文件、不重命名、不拆 builder、不批量修正风格或属性，也不增加只验证注释文字的测试。

## 兼容性与下游影响

无需破坏性变更。公开签名、错误变体及 kind/path、输入接受规则、feature、wire V1 和旧格式解码保持现有合同。唯一有意变化是部分人类可读错误摘要更具体，既有文档已不承诺显示文本稳定。

rs-http、rs-web、rs-mime、rs-magika 无需迁移；rs-ioc、rs-websocket 的 0.14 依赖升级不属于本轮范围。应用如果自行断言完整错误文本，应更新相应断言；业务分支继续使用类别和上下文访问器。不修改下游仓库或要求下游 all-features 验收。

## 验收与风险控制

1. CFG-001 正例及反例通过，安全摘要不包含 canary，标量尾部惰性行为和失败优先级保持。
2. 检查器报告 12 组规范示例；三组新例在默认及 full feature 下都可运行，中英文对应代码一致。
3. 中文设计解释与英文及实现一致，相对链接和锚点有效。
4. CFG-004 指定不变量均有准确英文 Rustdoc，无额外生产逻辑变更。
5. 集成阶段完成本 crate 默认/full 回归和 Rustdoc 检查；使用已有项目 CI 入口核对基础设施规则，不加入下游 all-features 测试。
6. 最终 diff 限于计划集合及直接必要的相关测试/文档；已有工作树改动保留。验证失败时按失败证据定位，不以泛化重构扩大范围。
